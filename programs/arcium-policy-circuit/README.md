# The confidential mandate policy circuit (PRD §11)

This is the **normative copy** of the Arcium Arcis circuit that decides whether a
proposed action is inside a *secret* mandate. `tests/arcium-circuit.test.ts` is a
TypeScript mirror of it; `tests/arcium-policy-circuit.test.ts` asserts that the
mirror still matches this file, so neither can drift from the other silently.

## Why it lives here and not only in a working tree

The circuit was written at `/home/ubuntu/arcium-probe/probe/`, **outside this
repository**. That is the whole of F44's second half: the hermetic mirror in
`tests/arcium-circuit.test.ts` transcribes a file no reviewer of this repository
can see, diff, or check. A mirror of an invisible source can only be wrong in one
direction — it cannot be corrected by reading the thing it mirrors.

So the source is committed here and that checkout is treated as a **build tree**:
it is re-synced *from* this directory, never the other way round. The two
directions matter, because a copy that is edited in both places is a copy that
will disagree.

## Building it

The toolchain problem is documented in the working tree's `BUILD-SBF.md`, and it
is a version skew rather than a misconfiguration: `anchor-cli` 1.0.2 predates
SBPFv3 and cannot forward `--tools-version`, so `arcium build` cannot be used.

```bash
export PATH="$HOME/.local/share/solana/install/active_release/bin:$PATH"
cd <working tree>/encrypted-ixs && cargo build --release          # the circuit
cd <working tree>/programs/probe && cargo-build-sbf --tools-version v1.57 --arch v1
```

## What this circuit deliberately does not do

Per PRD §11, "the enclave MUST NOT be the only enforcement layer". The circuit
computes a decision and nothing else: it does not move value, does not authorize
an execution, and cannot bind itself to a specific action. A decision from here is
an input to `validateExecutionBinding`, which re-derives independently. **An
`allowed = 1` produced by this circuit is not permission to move anything**, which
is the repository's load-bearing rule and the reason this file is small.

## The runbook (a localnet is not CI)

Two host prerequisites, neither documented by Arcium, and the second is the one that
masquerades as a client bug:

1. **The validator must bind a nameable address.** `bind_address = "0.0.0.0"` —
   the natural spelling of "listen everywhere" — makes Agave 4.3.0 panic with
   `UnspecifiedIpAddr(0.0.0.0)`, because it cannot derive a gossip external address
   from the unspecified one. Bind the docker bridge address (`172.17.0.1`).
2. **`ufw` must allow the docker subnets to reach the validator on 8899 *and* 8900.**
   With the default deny, the nodes resolve `host.docker.internal` correctly and then
   cannot reach anything. Missing **8900** (the WebSocket) is the nastier of the two:
   the nodes stay up, keep streaming gossip, and simply never connect pub/sub — so
   `MxeKeygen` never runs, the MXE public keys stay unset, and
   `getMXEPublicKey` returns `null` forever. That reads as a broken client.

```bash
sudo ufw allow from 172.17.0.0/16 to 172.17.0.1 port 8899 proto tcp
sudo ufw allow from 172.20.0.0/16 to 172.17.0.1 port 8899 proto tcp
sudo ufw allow from 172.17.0.0/16 to 172.17.0.1 port 8900 proto tcp
sudo ufw allow from 172.20.0.0/16 to 172.17.0.1 port 8900 proto tcp
```

Then, from the working tree:

```bash
arcium localnet --skip-build     # `arcium build` cannot work here; see BUILD-SBF.md
ANCHOR_PROVIDER_URL=http://127.0.0.1:8899 ANCHOR_WALLET=~/.config/solana/id.json \
ARCIUM_CLUSTER_OFFSET=0 npx ts-mocha -p ./tsconfig.json -t 1000000 "tests/**/*.ts"
```

**Expect the callback twice.** See F72: on a 2-node localnet the cluster submits
every callback twice in the same slot, and `awaitComputationFinalization` returns
whichever it saw first. The live suite does not use it.
